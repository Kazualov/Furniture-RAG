# RAG-система поиска офисных товаров

Гибридная RAG-система для семантического и полнотекстового поиска по каталогу офисной мебели и товаров, построенная на подмножестве **Amazon Open Source Dataset** (категория *Office Furniture*, ~700 000 товарных позиций).

Проект демонстрирует пошаговую эволюцию поисковой системы: от наивного точного векторного поиска до полноценной гибридной архитектуры с ранжированием по нескольким сигналам.

## Обзор

Задача проекта — построить производительную и точную систему поиска релевантных товаров по текстовому запросу пользователя. В основе лежит комбинация:

- **плотных (dense) эмбеддингов** для семантического сходства запроса и документа;
- **разреженного (sparse) поиска BM25** для точного лексического совпадения (артикулы, бренды, модели);
- **взвешенного объединения ранжирований (Weighted RRF)** для получения единого, более устойчивого результата, чем каждый из методов по отдельности.

## Датасет

- **Источник:** Amazon Open Source Dataset
- **Категория:** Office Furniture
- **Объём:** ~700 000 товарных карточек
- Используются текстовые поля товара (название, описание, атрибуты) для построения как векторного индекса, так и полнотекстового индекса.

## Архитектура

Система состоит из двух хранилищ данных, работающих совместно:

| Компонент | Назначение |
|---|---|
| **Qdrant** | Векторная база данных для хранения и поиска dense-эмбеддингов (размерность 384), с HNSW-индексацией и INT8-квантованием |
| **PostgreSQL** | Табличное хранилище товаров и полнотекстовый поиск BM25 |

Общая схема запроса:

1. Запрос пользователя параллельно обрабатывается двумя пайплайнами: dense-поиском в Qdrant и BM25-поиском в PostgreSQL.
2. Оба списка результатов с их ранжированиями передаются в модуль **Weighted RRF**.
3. Итоговый список формируется на основе взвешенного объединения рангов с оптимальным коэффициентом **α**.

## Технологический стек

- **Векторная БД:** Qdrant (индекс HNSW, квантование INT8 из FP32)
- **Реляционная БД:** PostgreSQL (полнотекстовый поиск BM25)
- **Эмбеддинги:** dense-векторы размерностью 384
- **Ранжирование:** Weighted Reciprocal Rank Fusion (RRF)

## Эволюция версий

Проект разрабатывался итеративно — каждая версия последовательно устраняет узкое место предыдущей (точность индекса → скорость → память → качество ранжирования):

### v1.0 — Baseline / Наивный подход
Чистый векторный поиск с **точным (Flat/Exact) индексом** и **тяжёлыми FP32-векторами**.
Полный перебор без приближений — эталон по точности, но самый медленный и затратный по памяти вариант.

### v1.1 — Оптимизация БД
Переход на **приближённый HNSW-индекс** при сохранении **FP32**-векторов.
Существенный прирост скорости поиска за счёт графовой индексации, при незначительной потере точности относительно baseline.

### v1.2 — Оптимизация модели
**HNSW-индекс + квантованные векторы (INT8)**.
Снижение объёма занимаемой памяти и дальнейшее ускорение поиска за счёт перехода с FP32 на INT8-представление эмбеддингов.

### v2.0 — Финальная гибридная система
**BM25 (PostgreSQL) + HNSW INT8 (Qdrant) + Rank Fusion** с подобранным оптимальным α.
Объединение лексического и семантического поиска даёт наиболее релевантные и устойчивые результаты, сохраняя при этом высокую производительность, достигнутую в предыдущих версиях.

## Метод ранжирования: Weighted RRF

Итоговое ранжирование строится на основе **Weighted Reciprocal Rank Fusion** — метода объединения нескольких ранжированных списков результатов (BM25 и dense-поиск) в единый список. Вес **α** контролирует относительный вклад каждого из источников и подбирается эмпирически для достижения наилучшего качества поиска.
